## 2026-11-10 evening — host affinity feature (task→worker pinning)
User asked: can dependent tasks be forced onto the same worker that ran an earlier task (avoid re-transferring files created on the previous host). Research: afanasy has NO host affinity — scheduler matches hosts only at Job/Block level (canRunOn, block.cpp:202), only static hosts_mask exists; no runtime setparams op. Chosen design (user picked option 3 + "affinity ON by default, webui job-param toggle"):
- Job-level fields in `libafanasy/job.h/.cpp`: `m_host_affinity` (int8, default 1 = ON), `m_host_affinity_giveup_sec` (int, default -1 never), `m_host_affinity_host` (anchor, persisted), `m_host_affinity_since` (giveup clock, persisted). Editable via `Job::jsonRead` params path (webui toggle works through existing jobs action `params`), serialized in `v_jsonWrite` (only non-defaults), restored from store JSON on restart. SQL/binary path (`v_readwrite(Msg)`) intentionally NOT changed — server runs nosql here; upgrade path: add serialization if PG is ever enabled.
- Enforcement in `server/jobaf.cpp` `JobAf::genTask()` next to existing `avoidHostsCheck` — single choke point for task dispatch. Anchor = last host a task was dispatched to (set in genTask); giveup = clock from last anchor dispatch (`hostAffinityCheck` in job.cpp). ponytail: clock-based giveup only, no render-availability query; re-anchor self-heals when tasks move.
- `afanasy/python/af.py`: `Job.setHostAffinity(on=True, giveup_sec=-1)`.
- `afanasy/browser/jobs.js`: AFF badge on every job row (click toggles host_affinity 0/1 via nw_Action params), shows anchor host in label, giveup info in tooltip. Note: badge renders AFF on all jobs from webui refresh even while the OLD afserver binary is running (it does not send the fields) — cosmetic until the new binary is live.
- NO afrender/worker changes needed: TaskExec wire message (taskexec.cpp v_readwrite, Msg::TTask) untouched — server just refuses to hand a task to the wrong render. Verified live: atomo render idle while game2 ran all pinned tasks; with affinity toggled OFF, both renders took tasks immediately.

Build: needed cmake on atomo (installed 3.31.6 via apt; machine had none — docker build machine elsewhere). In-source build works: `cd afanasy/src/project.cmake && rm CMakeCache.txt CMakeFiles; CMAKE_POLICY_VERSION_MINIMUM=3.5 ./build.sh --nosql --nogui -j8` (~1 min incremental; watch "Clock skew" warnings on NFS — harmless here, verified new symbols in binary via `nm -C | grep hostAffinity`). Old binary backed up: `afanasy/bin/afserver.jan5.preaffinity` (+ a stray `.2026-01-05.bak` copy exists). Running production afserver pid NOT touched (still old binary in memory; disk binary is the new one — swap happens at next restart, restart still requires user's explicit go).
